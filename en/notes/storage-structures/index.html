11 storage structures in databases and file systems

2026-11-26 · Storage

B-tree indexes keep keys in order, which supports both exact matches and range queries. Databases and file systems also need to decide what data they can skip, where file contents live, and where updates should go. The 11 diagrams below show structures used for these different jobs.

Comparison of all 11 structures

Structure Strength Trade-off Implementation or reference
B-tree Exact matches, range scans, and ordered traversal Updates can cause page splits. PostgreSQL B-tree
Trie / radix tree Looking up keys with a shared prefix Sparse branches can use extra memory. Radix variants compress paths. DuckDB ART
R-tree family Finding overlap with a geographic or geometric region Overlapping rectangles can require visiting multiple branches. SQLite R*Tree
Hash index Exact key matches Does not support ordered scans or range lookups. PostgreSQL Hash
Inverted index Looking up documents by term, tag, or array element One document update may affect entries for multiple terms. PostgreSQL GIN
BRIN Skipping block ranges in large, physically ordered tables Scattered values reduce pruning, and candidate rows still need rechecking. PostgreSQL BRIN
FAT cluster chain Following the clusters of a fragmented file Using the chain alone, random access requires following earlier links. exFAT §4.1
Extent Mapping a contiguous run with one record Fragmentation adds records. A tree can index those records. ext4
Allocation bitmap Representing used and free blocks compactly Finding a long free run requires scanning or auxiliary metadata. ext4
LSM-tree Batching writes while preserving ordered scans Reads may consult multiple files, and compaction rewrites data. RocksDB
Log-structured file system Grouping updates into sequential writes Cleaning old segments can require copying live blocks. F2FS

Combining structures in one system

Ext4 uses an extent tree to map logical file blocks to physical disk blocks, and bitmaps to track which blocks and inodes are in use. An extent is a record representing a contiguous run, so it can be stored in a tree that helps locate it. Ext4 block mapping · Ext4 bitmaps

An LSM-tree later merges files sorted by key. A log-structured file system writes updated blocks to new locations and changes where those blocks are referenced. Both can group writes. The work that follows differs: merging sorted runs in one case and reclaiming segments in the other. RocksDB compaction · F2FS design
